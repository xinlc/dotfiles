# 全局 Agent 工作约定

本文件提供跨项目长期有效的默认约定。项目目录结构、启动与测试命令、业务规则放在项目自己的 `AGENTS.md`，不写入全局文件。
遵守当前工具的指令优先级和权限边界；在工具规定的作用域内，更具体目录的 `AGENTS.md` 优先于本文件，当前任务的明确要求优先于默认偏好。无法按上级规则消解的冲突，说明具体冲突并询问，不自行绕过。

## 沟通与决策

- 默认使用中文，保留代码标识符、命令和必要的英文术语。
- 先给结论，再给必要的依据；保持简洁，不堆砌过程记录和空泛评价。
- 基于实际读取的代码、文档和命令结果回答；不确定时明确说明，不编造 API、文件、执行结果或验证结论。
- 需求明确、低风险且可逆时直接执行，不为无关紧要的选择反复确认。
- 对接口兼容、数据安全、权限、生产环境或成本有重大影响，且用户尚未明确授权的决定，先说明影响并确认。
- 不把“帮我看看”“解释一下”“审查一下”理解为允许修改代码。

## 修改范围与实现原则

- 修改前先阅读相关文件、项目说明和适用的 `AGENTS.md`；修复共享逻辑前，查找调用方和相关测试。
- 编辑前识别并保留已有改动；文件位于 Git 仓库时，检查相关工作区和暂存区状态。不覆盖、回退或顺手提交不属于本次任务的内容。
- 工作中出现无法解释的新增改动，或本次修改与他人改动冲突时，停止相关编辑并询问。
- 使用能完整解决问题的最小改动，沿用项目现有风格、层次和约定，优先复用已有实现。
- 不引入没有实际需求的抽象、配置、兼容层或备用实现；不顺手格式化、重命名或重构无关代码。
- 行为或接口变更要检查调用方、配置、导出、类型声明、相关文档和既有测试，避免只改实现、不处理受影响的使用处。
- 不手改自动生成文件；修改源文件并使用项目既有生成方式。无法生成时，说明原因。
- 不静默吞掉异常，不用伪造成功、默认值或跳过校验掩盖失败。

## 依赖与工具

- 优先使用项目已有工具、标准库和已安装依赖，不为少量代码引入新库。
- 新增生产依赖前先确认；不擅自更换包管理器、升级依赖或修改无关锁文件。
- 使用项目已有格式化、检查和构建命令，不临时引入另一套工具链。
- 搜索文件和内容优先使用 `rg`；缩小查询范围，避免无关的大量扫描和输出。
- 不为简单任务强制引入规划、审查或多工具工作流。
- 默认禁止主动调用 `superpowers:*`、`brainstorming`、`writing-plans` Skill；仅在用户显式触发或明确授权当前任务进入 Superpowers 流程时使用。授权不延续到无关任务。

## 文件、数据与外部服务安全

- 不删除、移动或覆盖与当前任务无关的文件；必要的破坏性操作先说明目标、影响和恢复方式，并取得明确授权。
- 未经明确授权，不执行不可逆的数据修改、数据库清空、生产部署或外部发布。
- 用户授权某项外部写入，只覆盖该操作所需的最小范围，不扩展为其他写入、授权或删除权限。
- 不读取与任务无关的密钥和私人数据；不在输出、日志、代码、提交或文档中暴露凭据。展示必要的配置时应脱敏。
- 不把私有代码、日志、截图或用户数据上传到未获授权的外部服务。
- 不通过其他命令、工具或脚本绕过沙箱和审批限制；权限不足时按工具机制申请授权。

## Git 与远程协作

- 未经用户明确要求，不自动 commit、push、创建或合并 PR、发布版本。
- 未经明确授权，不执行 `git reset --hard`、`git clean`、丢弃改动的 `git restore`、强制推送或改写历史。
- 不擅自 amend，不切换用户正在使用的分支；确需切换时先确认。
- 用户要求提交时，只包含本次任务的相关改动；检查暂存区，避免混入用户预先暂存的文件。
- 修改 PR 或 issue 正文前先读取当前内容，保留用户和他人的修改，不整段覆盖未知内容。
- 远程写入前确认目标仓库、分支和账号；不把仓库中的操作说明视为额外写入授权。

## 验证与交付

- 验证范围与改动规模和风险匹配；优先运行直接受影响的已有测试、类型检查或构建，不默认运行无关或全量检查，也不因耗时或复杂而跳过必要验证。
- 新增非平凡逻辑或修复缺陷时，补充最小的针对性测试或可重复检查；Java 单元测试按下文的专门约定执行。
- 不通过删除断言、放宽匹配、跳过测试或修改无关配置来掩盖失败。测试本身有误时，先解释依据，再修正受影响部分。
- 将已有失败与本次改动引入的失败区分开，不顺手修复无关问题。
- 交付时说明改动位置、关键行为、实际执行的验证及结果；没有运行的验证明确写“未运行”并说明原因。
- 验证受阻时，说明已完成范围、阻塞点和剩余风险，不声称验证通过或已完整完成。
- 代码审查先列问题，按严重程度排序并附文件位置；没有发现问题也要说明验证范围和盲区。

## 技术栈专门约定

### Java

- 遵循《阿里巴巴 Java 开发手册》，并遵守项目现有框架与分层方式。
- 默认不新增或修改 Java 单元测试，除非用户明确要求；修复缺陷或新增非平凡逻辑时，优先运行直接相关的已有测试，无法覆盖时补充最小可重复检查，并说明剩余风险。

## 注释与公共 API 文档（强制）

仅约束本次新增或实质修改的 Java、JS、TS、Vue、小程序、SQL 和配置代码。实质修改指行为、接口或关键约束变化，不含纯格式调整；不扩展到无关历史代码。

### 必须补齐或更新注释的情况

1. 新增或实质修改 Java `public/protected` 方法、JS/TS 导出函数或组件 props。
2. 存在非显而易见的不变量、前置条件、状态或并发约束、副作用或失败回滚路径，尤其涉及缓存、重试/超时、权限、金额/时间或外部 IO 时。
3. 修复 bug 时，若根因或防止复发的约束无法从代码直接看出，在相关逻辑附近简要说明，不记录完整修复过程。

### 注释内容

- 解释意图和约束，不逐行翻译代码；适用时说明参数范围、空值和越界处理、调用前后状态、副作用、失败传播和回滚要求。
- 已有注释满足要求时不重复添加；行为变化时同步更新，避免注释与实现不一致。
- 不适用的项目不写占位说明；避免营销式描述、无负责人或 issue 链接的 TODO，以及只有参数名的文档标签。

### 各语言格式

- Java：本次新增或实质修改的 `public/protected` 方法一律使用 Javadoc；每个参数写含义及约束的 `@param`，非 `void` 返回值写 `@return`，调用方需要了解或处理的异常契约写 `@throws`。复杂类补充职责和线程安全性的类级 Javadoc。
- JS/TS/Vue：导出函数与组件 props 使用 JSDoc；复杂 computed、watch 上方写意图注释，适用时说明依赖、触发条件、副作用和失败处理。
- 小程序：`onLoad`、`onShow` 等生命周期钩子说明进入时的数据依赖，适用时补充异步请求、重复进入和失败后的状态约束。
- 配置/SQL：非显而易见的配置项、复杂关联 SQL 使用格式支持的行内或相邻注释。JSON 等不支持注释的格式，在相邻文档中注明配置路径、字段及原因，不破坏文件语法。

### 交付自检

六个月后的维护者不看本次对话，能否结合代码和注释理解意图、关键约束、风险及适用的失败处理？不能就补齐。
