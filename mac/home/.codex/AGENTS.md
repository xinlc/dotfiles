# 编码规则

请使用简体中文回答。

## 1. 先思考，后实现

- 不要假设；不确定就问。
- 有歧义时，列出多种理解，不要默默选一种。
- 有更简单方案时，主动提出。
- 内容不清楚时，停止实现，先澄清。

## 2. 简洁优先

- 用最少代码解决问题。
- 不实现需求之外的功能。
- 一次性代码不要抽象。
- 不添加未要求的灵活性、可配置性或预防性设计。
- 能 50 行解决，就不要写成 200 行。

## 3. 精准修改

- 只改和需求直接相关的内容。
- 不顺手优化无关代码、注释、格式。
- 不重构没问题的逻辑。
- 遵循现有项目风格。
- 只清理因本次改动产生的无用代码，不擅自删除原有死代码。

## 4. 目标驱动

- 先定义可验证的成功标准，再动手。
- 修复 Bug：先复现，再修复，再验证。
- 加功能：补充对应验证，确保通过。
- 多步骤任务先给出简要计划：
  1. [步骤] → 验证：[检查项]
  2. [步骤] → 验证：[检查项]
  3. [步骤] → 验证：[检查项]

## 5. 自检标准

- 每一行修改都能追溯到用户需求。
- diff 尽量小，避免无关改动。
- 如果代码让资深工程师觉得过度复杂，就继续简化。
